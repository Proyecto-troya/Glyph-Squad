UI Blueprint

Everything a front-end developer needs to restyle or rebuild the interface without reading the TypeScript: the screens and how a user moves between them, the layout of each screen, every component with its class name and states, and the constraints the CSS must respect.

The UI is plain DOM built in TypeScript (no framework). All styling lives in one file, app/src/style.css. The class names below are the contract between the markup and the stylesheet.

2 · Page shell

Four regions wrap every screen

Logo · Leaf Plateheader.appbar
Demo-mode warningp.banner
Screen content, scrollsmain
MuestraResultadoEnviarTécnico

div#app holds these in order. Tab bar selector is nav, tabs are nav a, current tab is nav a.active.

  • App bar is sticky at the top. Markup: header.appbar > span.brand > span.brand-mark > svg.icon, then the text "Leaf Plate".
  • Demo banner is inserted right after the app bar only when no real model is loaded. Design for both cases: with and without it.
  • Main needs bottom padding taller than the tab bar, or the last button hides behind it.
  • Tab bar is fixed to the bottom. Each tab is a > svg.icon + text; the current one also has aria-current="page".
  • Content column is capped at 640px and centred; on desktop the tab bar is capped to the same width.
  • Top and bottom bars must add env(safe-area-inset-*) to their padding (notched phones, installed PWA).

6 · Constraints

Rules the CSS has to respect

  • Offline first. The app is a PWA that must work with no connection. No web fonts, no CDN stylesheets, no remote images. Everything ships in the bundle, and the whole download has a 20 MB budget shared with the model and audio.
  • Phone in a field. Target a small Android screen (about 360–400px wide) used outdoors: large text, strong contrast, large touch targets. Light theme only today.
  • Class names are the contract. The script only adds the classes listed in section 4. Renaming one means editing the matching file in app/src/ui/.
  • Inline widths belong to the script. .progress-fill and .bar-fill get style="width: N%"; do not override width on them.
  • The hidden attribute must win. Two file inputs are in the DOM with hidden; keep [hidden] { display: none !important }.
  • Empty text nodes. p.status, p.error and p.sentence are rendered empty and filled later; they should take no space while empty.
  • Every render rebuilds the DOM. The script replaces the whole shell on each state change, so entrance animations would replay on every tap. Keep motion to transitions on hover, press and width.
  • Quechua text. p.quz strings are long words; make sure they wrap inside cards.
